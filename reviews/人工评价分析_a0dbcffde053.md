# 两位同事的人工评价：能得出什么，不能得出什么

样本：45 个镜头 × 2 位评价人。评价人 A 只打分不写备注，评价人 B 写了 26 条备注。

---

## 结论先行

**备注有信号，评分没有。**

不要用这批评分去调阈值。理由在下面。

---

## 1. 评分本身不可靠

| | |
|---|---|
| 完全一致 | 27/45 = **60%** |
| Cohen's kappa | **0.236**（较弱） |
| A 的分布 | ok 25 / fix 20 |
| B 的分布 | ok 17 / fix 27 / 未评 1 |

60% 的一致率听起来还行，但在二选一、且两人倾向不同的情况下，kappa 0.236 意味着**扣掉碰巧一致的部分，剩下的一致性很有限**。

更直接的证据 —— 按"调色让画面暖化了多少"分档看"需要修"率：

| 暖化量 | 镜头数 | 需要修 |
|---|---:|---:|
| −100 ~ −20 mired | 8 | 56% |
| −20 ~ −8 | 5 | 30% |
| −8 ~ +8 | 9 | 61% |
| +8 ~ +20 | 10 | 50% |
| +20 ~ +100 | 13 | 54% |

**完全没有单调性。** 如果暖化量在驱动评分，这一列应该随幅度上升。它没有。

还有一个反向证据：两人都判"要修"的镜头暖化中位 **+9.0** mired，两人都判"可以"的是 **+13.1** mired —— **被一致认可的镜头反而被改得更多**。

所以：评分列不能用来标定任何阈值。

---

## 2. 但备注里有真信号

B 的 26 条备注按内容归类：

| 类型 | 条数 |
|---|---:|
| 偏黄 / 黄调过重 | **14** |
| 偏色（未指明方向） | 5 |
| 光线爆 | 3 |
| 偏蓝 / 阴影发蓝 | 2 |
| 饱和对比过强 | 2 |

把这些和实际测量对上：

```
备注含「黄」的 14 个镜头： 调色暖化中位 +17.7 mired
其余         31 个镜头： 调色暖化中位  -0.1 mired
                        相关系数 +0.30

备注含「爆」的  5 个镜头： 亮度中位数变化 +0.1045
其余         40 个镜头：                 +0.0678
```

**B 的眼睛在检测真实存在的东西。** 他说偏黄的镜头，确实是被暖化最多的那批。他说光线爆的，确实是被提亮最多的那批。

（顺带：全片抽样 23 个镜头，色温变化中位 **−0.1 mired**，8 个变暖、8 个变冷、7 个不变。所以"整片偏黄"并不成立——是**特定镜头**被暖化了 +20 到 +50 mired，而人对这个很敏感。）

---

## 3. 两个明确的技术结论

### 3a. 曝光需求量是唯一在两人之间都成立的预测因子 ✅

| | 判 fix 的镜头 | 判 ok 的镜头 |
|---|---:|---:|
| A：\|请求 EV\| 中位 | **0.51** | 0.25 |
| B：\|请求 EV\| 中位 | **0.51** | 0.32 |

**两个人独立地在同一个方向上。** 系统想做大幅曝光调整的镜头，就是人想要返工的镜头。

这条支持保留 `highlight_limited` 标记，而且给出了一个可用的分界：**请求 EV 超过 0.5 的镜头应该直接进局部校正清单**，不要指望全局曝光能处理。

### 3b. 肤色色相旋转不预测人的判断 ❌

| | 判 fix | 判 ok |
|---|---:|---:|
| A：肤色旋转中位 | 5.8° | 5.3° |
| B：肤色旋转中位 | 5.1° | **6.8°** |

A 几乎没差别，B 是**反的**。

这不是说 ΔH 这个度量错了（它在 Golden Set 上是干净的、与曝光无关的），而是说：**6° 这个阈值标出来的镜头，不是人觉得有问题的镜头。**

两种可能，这批数据分不出来：
- 人在这个量级上根本注意不到色相旋转（那阈值该放宽很多）
- 人注意到的是别的东西（饱和度、明暗对比），肤色色相只是恰好同时出现

**不要基于这批数据动这个阈值。** 需要一次针对性测试（见第 5 节）。

---

## 4. 我这份复核表设计得不对

15 条 B 的备注写在被标为 `highlight_limited`（曝光问题）的镜头上，内容却全是颜色：

```
shot_0031  highlight_limited  →  "偏色了"
shot_0036  highlight_limited  →  "阴影发蓝"
shot_0063  highlight_limited  →  "偏蓝"
shot_0085  highlight_limited  →  "黄调过重"
shot_0103  highlight_limited  →  "饱和度对比太强"
```

我给每个镜头写了一个针对性问题（"主体是否还是太暗？"），但页面上摆的是完整的原片/成片对照。**人看到整幅画面，回答的是"这一版好不好"，不是我问的那个问题。**

这不是评价人的问题，是**我的问卷设计问题**。而且他们回答的那个更宽的问题其实更有价值——只是我没有为它设计记录方式，所以只能从自由文本里挖。

另外 A 完全没写备注、评分也和任何可测量的量都对不上，我倾向于认为 A 那一列的信息量很低。这本身也是问卷的问题：没有强制的结构化输入，就只能得到最省力的回答。

---

## 5. 下一轮该怎么做

### 改问卷

| 现在 | 改成 |
|---|---|
| "可接受 / 需要修 / 不确定" | **强制二选一**：哪一版更好？（左 / 右） |
| 固定 左=原片 右=成片 | **随机左右 + 不标注哪边是哪边**（盲测） |
| 自由文本备注 | **结构化标签**：偏黄 / 偏蓝 / 太亮 / 太暗 / 肤色不对 / 对比过强 / 说不上来 |
| 每个镜头看一次 | **插入 5 个重复镜头**，用来量同一个人的自洽程度 |

盲测 + 强制二选一解决了最大的问题："可接受"这个词每个人的标准不同，而"哪个更好"是同一个尺子。重复镜头则能立刻告诉我们某位评价人的数据能不能用——如果一个人对同一镜头两次给出相反答案，他那一列就该丢掉。

### 针对肤色阈值的专项测试

现有数据分不出"人注意不到"还是"人在看别的"。做法：取同一个镜头，人工生成一组只改肤色色相的版本（3°、6°、9°、12°、15°），随机顺序给人看，问"和原片比有没有色偏"。这能直接量出**人的察觉门槛**，然后把 `SKIN_HUE_ROTATION_LIMIT` 定在那个位置。

这个测试不需要新素材，用现有的 Golden Set 肤色面板加真实镜头都可以。

### 关于「暖化」的假设

B 的备注指向一个具体假设：**+20 mired 以上的暖化会被注意到并被认为过头。** 当前 `MAX_CORRECTION_MIRED = 40`。

但我不建议现在改。相关系数只有 0.30，而且评分列没有支持它。这正是我前几轮反复踩的坑——**在噪声上调尺子**。等盲测数据出来再定。

---

## 6. 一句话

这批数据最值钱的不是"通过率多少"，而是告诉我们：

- **曝光需求量是真信号**（两人一致，方向明确）→ 可以直接用
- **肤色色相阈值没有被验证**（一人无关、一人反向）→ 需要专项测试
- **问卷本身需要重做**（人回答的不是我问的问题）→ 这是下一轮的前提

第三条最要紧。在问卷修好之前再找更多人来看，只会得到更多不能用的数据。
