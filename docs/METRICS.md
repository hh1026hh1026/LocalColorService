# 指标定义（冻结）

**这份文档的目的**：让"改进"可以被证明，而不是被声称。

在 V0.6 和 V0.6.2 两次发布里，算法和衡量算法的指标被同时修改，导致 before/after 数字是用不同尺子量的，无法比较。这份文档冻结指标定义，此后：

> **改算法不改指标。确需改指标时，新旧两套并行输出至少一个版本，并在变更说明里同时给出两套数字。**

指标版本：**METRICS v1**（V0.6.4 起）

---

## 1. 白平衡 / 光源估计

### `source_cct_kelvin` / `source_duv` / `mired_offset_from_d65`

- **定义**：从 `rgb_gains` 反推场景光源白点（线性 Rec.709 → XYZ），再用 Ohno 2013 转成 CCT/Duv。
- **单位**：Kelvin / Duv 无量纲 / mired（`1e6/CCT - 1e6/6503.5`）
- **误差报告一律用 mired**，不用 Kelvin。Kelvin 在高色温端不是感知均匀的：6000→6500K 和 3000→3500K 的视觉差异相差一个数量级。
- **弃用**：`estimated_temp_offset`（= `gain_b - gain_r`，无量纲无物理含义）。字段保留供旧报告回退，新代码不得使用。

### 测量范围 vs 应用范围（必须区分）

| | 范围 | 位置 |
|---|---|---|
| **测量**允许表达的增益 | `[0.35, 4.50]` 线性 | `white_balance.LINEAR_GAIN_MIN/MAX` |
| **应用**到配方的增益 | `[0.80, 1.25]` 线性 | `correction_engine`、`group_white_balance` |

测量范围宽是为了**如实报告**（2500–15000K 都能表达）；应用范围窄是为了**安全**。两者不可混用。曾经用同一个 `[0.70, 1.45]` 兼任两职，导致 3200K 钨丝灯被饱和成 4392K。

## 2. 曝光

### `requested_exposure_ev` / `exposure` / `exposure_headroom_ev`

- **EV 一律在线性光下计算**：`EV = log2(target_linear / current_linear)`
- `requested_exposure_ev`：测量要求的量，**未经任何夹取**
- `exposure`：实际写入配方的量（先 ±0.8 安全夹取，再高光余量夹取）
- `exposure_headroom_ev`：由源片线性亮度百分位反推的上限，使引入的高光裁切 ≤ 2%
- `exposure_anchor`：`skin_anchor` / `frame_median` / `preserve`
- `highlight_limited`：为保护高光而削减了提亮 —— **这批镜头是真正需要局部校正的**

不要用 `exposure` 单独衡量"系统调了多少"，要看 `requested_exposure_ev` 与 `exposure` 的差。

---

## 3. 肤色安全

### 判据：`skin_delta_hue`（ΔH\*）与 `skin_hue_rotation_deg`

- **只用色相判定，不用总色差。**
- **理由（实测）**：ΔE2000 与 |EV| 的相关系数 **0.813**。一次 +0.8 EV 提亮必然大改肤色 L\*，ΔE2000 随之变大，但那是调色意图不是缺陷。CIELAB 的 ΔC\* 同样随亮度缩放，也不能用。
- 六色肤色面板实测：纯曝光变化 |ΔH\*| < 0.05；`tint +0.25` 达 4.6；`cold_thriller` 4.9；`day_for_night` 16.5。**色相干净地区分开了。**
- ΔH\* 用 CIE 定义 `2·√(C1·C2)·sin(Δh/2)`，与 ΔE 同单位。

| 字段 | 用途 |
|---|---|
| `skin_delta_hue` | **判据**，阈值 3.0 |
| `skin_hue_rotation_deg` | **判据**，阈值 6.0°（vectorscope 读数） |
| `skin_delta_lightness` | 仅记录 |
| `skin_delta_chroma` | 仅记录（受亮度污染） |
| `skin_delta_e2000` | 仅记录 |

### 另一类：`skin_clipped`

成片肤色任一通道 ≥ 0.98 → 单独归类。这不是"色相偏移"而是"颜色已经没了"，处理方式不同（降曝光而非降 Look 强度）。

## 4. LUT 质量（按 transform 角色分流）

**同一张 LUT 在不同角色下有不同判据。传错角色会产生大量不可操作的误报。**

| 角色 | 检查 | 明确不检查 |
|---|---|---|
| `technical` | 中性轴色度漂移 ≤ 0.040、单调性 | ❌ 绝对中性保持（白平衡本来就移动中性轴）<br>❌ `[0,1]` 出界（正曝光必然出界） |
| `creative` | 单调性、色域外映射、肤色旋转 ≤ 12° | ❌ 中性保持（Look 可以有意偏色） |
| `combined` | 单调性、肤色旋转 ≤ 18° | ❌ 中性轴漂移（含创意层，允许亮度相关偏色） |

### `neutral_axis_chromaticity_drift`

- **定义**：中性灰阶上 rg 色度（`r/(r+g+b)`, `g/(r+g+b)`）的**变化幅度**，只取 0.15–0.95 区间，排除贴边采样。
- **不是**绝对偏离。白平衡均匀平移整条轴是正常的；轴**张开**才是缺陷。
- 实测基线：合法技术校正 0.000–0.026；V0.6 前的对数域 slope 缺陷 0.068–0.157。阈值 0.040 落在中间。

### 已弃用的指标

- `neutral_axis_max_spread`（绝对偏离）—— 保留字段但不作判据
- `max_curvature` —— **保留记录但不发警告**。实测合法 LUT 曲率 0.081–0.276，缺陷 LUT 0.149–0.197，**合法的比缺陷的还高**，无区分力。要做 banding 检测必须测渲染后画面，不是 LUT 网格。

## 5. 连续性

| 指标 | 定义 | 阈值 |
|---|---|---|
| 亮度跳变 | 相邻镜头**显示域**亮度中位数之差 | 0.25 |
| 白平衡跳变 | 相邻镜头 `mired_offset_from_d65` 之差 | 25 mired |

- 亮度用显示域（感知比较，显示域是对的）；白平衡用 mired（物理量）。
- **组内跳变与跨组跳变分别统计**：组内是缺陷（同一光位本该一致），跨组通常是有意的剪辑点。
- `content_flags.preserve_intent` 的镜头（黑场、淡变）不计入。
- 旧的 `abs(estimated_temp_offset差) × 50 > 12` 已废弃，仅在旧报告缺少 CCT 时回退。

## 6. QC 状态分层

```
render_integrity   ┐
base_correction    │
creative_transform ├→ final_decision（取最差）
scene_continuity   │
skin_safety        ┘
```

`PASS` < `PASS_WITH_WARNINGS` < `NEEDS_REVIEW` < `FAIL`

- `within_group_continuity` 单独成项：组内跳变 → `NEEDS_REVIEW`，跨组 → `PASS_WITH_WARNINGS`
- `technical_color` 保留为 `base_correction` 与 `creative_transform` 的较差者（兼容旧调用方）

## 7. Golden Set 基线

`scripts/build_golden_set.py` 生成，`tests/test_golden_set.py` 断言。

### 用哪张图测什么（重要）

| 图 | 用途 | **不能**用来测 |
|---|---|---|
| `neutral_scene_<cct>` | **光源估计精度** | — |
| `colorchecker_<cct>` | LUT 色彩精度、ΔE | ❌ 光源估计 |
| `skin_panel_<cct>` | 肤色 ΔH/ΔC、灰世界失效场景 | ❌ 光源估计 |
| `gray_ramp` | 中性轴、往返精度、banding | — |

**ColorChecker 不是合格的光源估计目标。** 24 个刻意饱和的色块本来就不满足灰世界假设，用它打分测的是"图卡违反假设的程度"而不是估计器的精度。

V0.6.4 第一版正是踩了这个坑：用 ColorChecker 测出"3200K 钨丝灯误差 158.8 mired"，据此判定估计器无法处理钨丝灯。换成假设成立的场景后，同一个估计器对 3200K 的误差是 **0.0 mired**。

`neutral_scene_*` 由构造保证线性平均为中性（成对生成互补色偏），所以是唯一公平的光源估计目标。

### 当前实测（METRICS v1，V0.6.5）

| 项 | 结果 | 状态 |
|---|---|---|
| 光源估计 @ D65（公平场景） | 0.1 mired | ✅ |
| 光源估计 @ 3200K | **0.0 mired** | ✅ |
| 光源估计 @ 4300K | 0.1 mired | ✅ |
| 光源估计 @ 9000K | **0.0 mired** | ✅ |
| 50% 肤色 + 50% 背景（排除肤色后） | 0.0 mired | ✅ |
| **满屏肤色 @ D65** | **79 mired** | ❌ **已知缺口** |
| ColorChecker @ D65（参考，非判据） | 26.7 mired | — 预期 |
| 中性灰阶恒等往返 | < 2e-3 | ✅ |
| 白平衡后中性轴色度漂移 | < 5e-3 | ✅ |
| 纯曝光的肤色 ΔH\* | < 0.5 | ✅ |

### 剩余的一个已知缺口

**满屏肤色击败灰世界**：人脸特写把主体当成光源，D65 下估成约 4300K。画面里没有非肤色像素可用，排除机制无从下手。

缓解：应用增益被 `[0.80, 1.25]` 限制（损害有界）+ SceneGroup 共识（C2）在真实剪辑中会覆盖它。由 `tests/test_golden_set.py` 以当前实测值钉住。

### 已修复（V0.6.5）

- ~~强钨丝灯下估计器放弃~~ → 原因是**测试场景选错**（见上）。真正的缺陷是 agreement 在**增益空间**衡量，导致偏离 D65 越远越容易被误判为不可信。改在 **mired 空间**衡量后，一个本可精确求解的 9000K 场景从"放弃（42.6 mired）"变成 0.0 mired。
- ~~估计器丢弃低置信度结果~~ → 不再返回单位增益。估计**始终上报**，置信度如实标注，由 `correction_engine`（>0.60 才应用）和 C2 共识决定怎么用。丢弃估计等于让"读不出光源的镜头"和"真正中性的镜头"无法区分。
- **肤色排除必须以人脸检出为前提**：YCrCb 肤色分类器是宽色域范围而非人脸检测器，在零人脸的合成场景上它选中 16–90% 的像素（木头、泥土、暖色表面都符合）。无差别排除会破坏中性平均，实测把 0.1 mired 变成 61.7 mired。

## 7b. 人工基准（METRICS v1.1，V0.6.8）

Golden Set 回答"准不准"，人工基准回答"**够不够好**"。两者不能互相替代。

基准：`reviews/review_a0dbcffde053(1).csv`，45 个镜头，单一评价人。

### 唯一被人工验证的阈值

| | |
|---|---|
| `LARGE_EXPOSURE_CORRECTION_EV` | **0.50** |
| 依据 | 45 镜头复核中唯一能区分"需要修 / 可接受"的量 |
| 分离度 | AUC **0.715**（fix 中位 0.51 EV，ok 中位 0.32） |
| 交叉验证 | 第二位评价人独立得到同方向（0.51 vs 0.25） |
| 取 0.50 而非 Youden 最优 0.35 | 精确率 0.82 vs 0.75；四分之三为真的清单会被跳读，五分之四为真的会被读完 |

各标记在同一批复核数据上的精确率：

| 标记 | 标出 | 精确率 | 召回 |
|---|---:|---:|---:|
| `skin_hue_shift` @ 6° | 25 | **0.56** | 0.52 |
| `highlight_limited` | 28 | 0.71 | 0.74 |
| `large_exposure` @ 0.50 EV | 17 | **0.82** | 0.52 |
| 曝光 + highlight_limited | 32 | 0.72 | **0.85** |

复核清单现在用最后一组。

### 被人工数据否定的假设

| 假设 | 结果 |
|---|---|
| 肤色色相旋转越大越该修 | **反向**（fix 5.1° vs ok 7.0°，AUC 0.366）。阈值从 6° 放宽到 20°，仅保留无争议的旋转 |
| 暖化越多越该修 | **不成立**（有符号 AUC 0.390、绝对值 0.523）。ok 的镜头暖化中位 +15.9 反而高于 fix 的 +2.1。**`MAX_CORRECTION_MIRED` 保持 40 不变** |
| 对比度提升导致去饱和，需要补偿 | **实测推翻**：对比度 1.10 让饱和度**上升** +0.047。该修法不存在 |

### 这个基准的局限（用之前必读）

1. **只有一位评价人**（第二位 kappa 仅 0.236，判断不可靠）。
2. **只能衡量误报，不能衡量漏报** —— 复核表里只有系统已经标出的镜头，系统漏掉的没人看过。表中"召回"只是"在已标出范围内的召回"。
3. **n=45**，单个项目、单一素材。
4. 评价人的备注与评分高度耦合（26 条备注对应 25 个 fix），所以两者不是独立证据。

**因此：`LARGE_EXPOSURE_CORRECTION_EV = 0.50` 是一条待复核的经验值，不是定论。** 下一批盲测数据到位后应重新拟合。

## 8. 修改本文档的规则

1. 改指标定义 → 必须同时更新 `tests/test_golden_set.py` 的基线值，并在变更说明里给出新旧两套数字
2. 放宽任何阈值 → 必须写明放宽的实测依据
3. 收紧阈值（能力提升）→ 更新第 7 节的表格，这是进展的唯一记录方式
4. 新增指标 → 先想清楚它会不会被别的量污染（ΔE2000 被曝光污染就是没想清楚的后果）
